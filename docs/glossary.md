# 용어 사전 (초안)
 
- 상태: 초안. 설계 주간에 요구사항·ERD와 함께 보강한다.
- 규칙: 코드, 문서, 화면, 이슈, PR에서 같은 것은 같은 말로 부른다. 새 용어가 생기면 여기에 먼저 적는다.
- 구성: 서비스 안에서 쓰는 말(도메인 용어)과, 개발하면서 쓰는 말(개발 용어)로 나눈다.
- 11/7: ADR-0007(로그인과 인증), ADR-0008(받기와 로그인)을 반영했다.

### 쓰지 않는 말
 
- **"배포"는 서버에 올리는 것(deploy)에만 쓴다.** 템플릿을 나눠 주는 것은 "받기", "드롭", "라이브러리에 추가"로 쓴다.
- **"구매"는 쓰지 않는다.** 결제가 없으므로 "받기", "라이브러리에 추가"로 쓴다.
- **"1인 1개"는 쓰지 않는다.** 본인인증이 없어 사람을 셀 수 없으므로 "계정당 1개"로 쓴다(ADR-0007).
### 정해진 규칙
 
- **받기와 로그인**: 사람마다 세어야 하는 것(드롭, 라이브러리, v2 좋아요, 보류 층의 유료 구매)에만 로그인을 요구한다(ADR-0008).
- **드롭은 계정당 1개**이고, 확인된 회원만 받을 수 있다. 본인인증이 없으므로 한 사람이 계정을 여러 개 만드는 것은 막지 못한다(ADR-0007·0008).
- 드롭 조건 안에서 라이브러리에 추가한 사람은, 드롭이 끝난 뒤에도 계속 다운로드할 수 있다.

| 출처 (origin) | 주소의 앞부분 세 가지: `https` + 도메인 + 포트. 셋이 모두 같으면 "같은 출처"다. 예: `https://example.com`과 `https://example.com/api`는 같은 출처, `https://api.example.com`은 다른 출처 | ADR-0005. 화면과 API를 같은 출처에 둔다 |
| 같은 사이트 (same-site) | 출처보다 넓은 묶음. 도메인의 끝부분(예: `example.com`)이 같으면 같은 사이트다. `api.example.com`과 `example.com`은 다른 출처지만 같은 사이트 | 쿠키의 `SameSite` 설정이 이 묶음을 기준으로 한다(ADR-0007) |
| CORS | 다른 출처의 화면이 우리 API를 부를 때, 서버가 "이 출처는 허락"이라고 답해야 브라우저가 응답을 화면에 넘겨주는 규칙. 같은 출처면 필요 없다 | ADR-0005. 같은 출처라서 쓰지 않는다 |
| 제3자 쿠키 | 지금 보고 있는 사이트가 아닌, 다른 사이트의 쿠키. 사파리 등은 기본으로 막는다 | 화면과 API를 다른 도메인에 두면 로그인 쿠키가 이렇게 된다(ADR-0005 버린 선택지) |
| SPA | 처음에 HTML 한 장과 JS를 받고, 그 뒤 화면 전환은 브라우저 안의 JS가 하는 방식. 조립식 가구처럼 집(브라우저)에서 조립한다 | 프론트 방식(ADR-0005) |
| 서버 렌더링 (SSR) | 서버가 페이지마다 내용이 채워진 HTML을 만들어 보내는 방식. 완성품 배달에 가깝다. Next.js가 대표적이다 | 쓰지 않는다(ADR-0005) |
| 정적 파일 | 요청마다 바뀌지 않는 파일(HTML·JS·CSS·이미지) | 프론트 빌드 결과. Nginx가 그대로 준다 |
| 리버스 프록시 | 손님의 요청을 먼저 받아서 뒤의 알맞은 서버로 넘겨주는 문지기. 넘길 때 "원래 손님의 IP, https로 왔는지, 원래 주소"를 메모로 붙인다 | Nginx: `/api`는 Spring으로, 나머지는 화면 파일로. 개발 때는 Vite 개발 서버가 같은 일을 한다 |
