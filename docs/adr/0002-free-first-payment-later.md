# ADR-0002: 무료 받기를 전제로 하고, 결제는 나중에 붙일 수 있게만 만든다
 
- 날짜: 2026-11-05
- 상태: 승인 (2026-11-05, 정현)
- 작성: 초안은 멘토 AI, 검토·승인은 정현
## 맥락
 
- 사이트가 안정되면 유료 판매, 올린 사람이 직접 정하는 가격까지 가능성으로 생각하고 있다.
- 실제로 돈을 받으려면 사업자 등록, 통신판매업 신고(면제 기준이 있어도 PG가 신고번호를 요구할 수 있음), PG 계약이 필요하다. 다른 사람이 팔게 하면 통신판매중개자로서의 의무(거래 당사자가 아님을 고지, 판매자 신원 확인·제공)와 정산 문제가 더해진다.
- 학생 개인의 취업 포트폴리오 범위에서 감당하기엔 법·세무 부담이 개발보다 크다. 이것은 기술이 아니라 사업 결정이다. (법·세무 내용은 전문가 확인 전 단계이며, 실제로 도입할 때 관할 기관·세무사에게 확인한다.)
## 선택지
 
1. 지금 유료 판매까지 구현한다 (실제 결제)
2. PG 테스트 결제로 결제 흐름만 구현한다
3. 무료만 운영하고, 결제를 나중에 붙일 자리만 남긴다
4. 무료만 운영하고, 결제는 고려하지 않는다
## 결정
 
**3번.**
- "라이브러리에 추가"는 처음부터 내부적으로 **주문**으로 만든다. 주문은 금액(지금은 항상 0)과 상태를 가진다.
- 화면에는 "0원" 대신 **"무료"**로 표시한다.
- 결제 테이블, PG 연동, 정산은 만들지 않는다. 실제로 필요해질 때 만든다.
버린 이유:
- 1번: 위의 법·세무 부담. 졸업 뒤 사업으로 판단할 일이다.
- 2번: 실제로 운영하는 사이트에 가짜 결제가 섞이면 사용자가 혼란스럽고, 4주 범위를 넘는다.
- 4번: 나중에 결제를 붙일 때 "다운로드 기록"을 "주문"으로 갈아엎어야 한다. 지금 주문으로 만드는 비용은 거의 없다.
## 결과
 
- 주문의 상태 설계(예: 생성 → 완료)와 테이블 구조는 설계 주간에 정한다.
- 용어 사전에 "주문"을 넣는다(화면에서는 "라이브러리에 추가", 가격은 "무료"로 표시).
- 결제를 도입하게 되면 이 ADR을 고치지 않고, 새 ADR이 이 결정을 대체한다.

## 정현의 판단 (대화에서 옮김)
 
> 정현의 말을 대화에서 옮겼다. 읽기 쉽게 조금 다듬었지만 뜻은 바꾸지 않았고, 정현이 말하지 않은 이유는 넣지 않았다. 이 칸은 11/5 규칙을 도입할 때 덧붙였고, 결정 내용은 그대로다.
 
- **처음 생각** (11/4): "다른 사람이 올리는 기능도 생각했고, 사이트가 어느 정도 안정되면 결제해서 다운받는 것도 생각했었습니다. 올린 사람이 가격을 정해서 올리는 것도요."
- **결정** (11/5): "결제는 염두에만 두고(정말 나중에 결제 시스템을 도입할 가능성만), 결제 시스템이 들어와도 큰 변경 없이 가능하게끔만 만들고 무료 다운로드를 전제로 하죠."
- **표시** (11/5): "0원 주문은, 0원이면 무료라고 바꿔서 적도록 하죠."
