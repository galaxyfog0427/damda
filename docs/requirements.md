# 요구사항 (v1)
 
- 날짜: 2026-11-12
- 상태: 승인 (2026-11-12, 정현)
- 범위: v1 = M4(12/20)까지. v2 이후와 보류는 4번
- 작성: 초안은 멘토 AI, 판단은 정현
> **쉽게 말하면**
> 1. 누구나 로그인 없이 템플릿을 둘러보고 받는다. 회원이 받으면 라이브러리에 담긴다.
> 2. 드롭(수량·기간 한정)은 로그인한 회원만 받고, 계정당 1개다. 드롭 템플릿은 일반 받기로 받을 수 없다.
> 3. 가입은 이메일로 받은 코드를 넣어야 끝난다. 만 14세 이상만 가입한다.
> 4. 템플릿은 공식 제작자 계정이 올리고, 운영 계정(비밀번호 + 패스키)이 공개한다.
> 5. 가입·로그인·재설정은 어떤 이메일이 가입되어 있는지 문구로도, 응답 시간으로도 드러내지 않는다.
 
## 0. 읽는 법과 v1 완료 기준
 
- 각 줄의 ID(B-1, D-2 …)는 이슈·PR·테스트 이름에서 이 줄을 가리킬 때 쓴다.
- [잠정: 언제] = 모양은 정했고 세부(숫자, 이름, 문구)는 그때 정한다.
- 근거 칸의 ADR은 `docs/adr/`에 있다. "기획"은 일정과 범위를 정한 비공개 기획 문서다. "정현 11/12"의 원문은 6번에 있다.
v1 완료 기준 (아래가 모두 되면 `v1.0.0`):
1. 공개 URL(HTTPS, `damda.dev`)에서 상시 가동하고, main에 병합하면 자동으로 배포된다.
2. 2번의 기능이 동작하고, 템플릿이 20개 이상 있다.
3. 메트릭 대시보드와 Slack 알림이 있다. 앱이 죽으면 서버 안의 감시가, 서버가 통째로 멈추면 서버 밖의 감시가 알린다. 백업이 서버 밖에 있고, 복구 리허설을 1번 했다.
4. README에 숫자가 있는 문제 해결 이야기가 2개 이상 있다(드롭 부하 테스트의 개선 전후 수치, 가상 스레드 켜고 끄기).
5. ADR, 용어 사전, API 문서가 저장소에 있다.
## 1. 사용하는 사람
 
| 누구 | 무엇으로 구별 | 할 수 있는 것 |
| --- | --- | --- |
| 방문자 | 로그인하지 않음. 서버에 세션이 없다 | 둘러보기, 일반 템플릿 받기 |
| 회원 | 이메일·비밀번호로 로그인. 가입 때 이메일을 확인했다 | 방문자 + 라이브러리, 드롭, 내 정보, 탈퇴 |
| 공식 제작자 계정 | 회원 + CREATOR 역할 + 공식 제작자 프로필 | 회원(탈퇴 빼고, A-10) + 제작자 화면(템플릿 등록·수정) |
| 운영 계정 | ADMIN 역할. 비밀번호 + 패스키 | 운영 화면(공개·내리기, 드롭 개설) |
 
- 공식 제작자 계정과 운영 계정은 서로 다른 로그인 계정이다(ADR-0007 4-4).
- 두 계정도 일반 가입으로 만든다. 역할(CREATOR·ADMIN)과 제작자 프로필은 운영 서버에서 런북 절차로 붙인다. 화면에서 역할을 주거나 빼지 않는다(ADR-0007 4-2).
## 2. 기능 요구사항
 
### 2-1 탐색 (B)
 
| ID | 요구사항 | 근거 |
| --- | --- | --- |
| B-1 | 공개된 템플릿 목록을 최신순(처음 공개한 시각)으로 본다. 목록은 쪽으로 나눈다 [잠정: 11/13, 쪽 번호 vs 커서] | 기획: v1 범위 |
| B-2 | 카테고리 하나와 형식(노션·PPT) 하나로 거른다. B-3과 함께(AND) 쓸 수 있다. 템플릿 하나는 카테고리 하나(6개 중)에 속한다 | 기획: v1 범위, 정현 11/12 |
| B-3 | 제목으로 검색한다. 제목에 검색어가 들어 있으면 나온다(부분 일치, 영문 대소문자 무시). 빈 검색어는 전체 목록이다 | 기획: v1 범위 |
| B-4 | 템플릿 상세에서 제목, 설명, 썸네일, 형식, 카테고리, 받은 수, 제작자(공식), 가격 "무료"를 본다 | 기획: v1 범위, ADR-0002 |
| B-5 | 템플릿 상세 주소를 메신저·SNS에 붙이면 링크 미리보기 카드가 뜬다(공통 카드) | ADR-0005 결정 4 |
| B-6 | 목록·상세·검색·받기에는 **공개된** 템플릿만 나온다. 내린 템플릿과 공개 전 템플릿은 나오지 않는다(주소를 알아도 상세가 열리지 않는다). 예외는 D-7 하나다 | |
 
### 2-2 받기와 라이브러리 (D)
 
| ID | 요구사항 | 근거 |
| --- | --- | --- |
| D-1 | 일반 템플릿(드롭 전용이 아닌 공개된 템플릿)은 로그인 없이 받는다. 받기는 POST이고 CSRF 토큰이 필요하다. 방문자에게 세션을 만들지 않는다. 드롭 전용 템플릿은 이 받기로 받을 수 없다(R-3) | ADR-0008 결정 1·3 |
| D-2 | PPT는 만료되는 다운로드 링크를 받는다. 노션은 복제 링크를 받는다 [잠정: 11/13, 만료 시간은 9번 결정] | ADR-0008 |
| D-3 | 받은 수는 받기가 링크를 내준 횟수다. 방문자는 받을 때마다 1을 더한다. 회원은 주문이 생길 때 한 번만 더한다(일반은 처음 받을 때, 드롭은 담을 때). 라이브러리에서 다시 받는 것은 세지 않는다. 탈퇴해도 줄지 않는다 | ADR-0008 결정 1, 정현 11/12 |
| D-4 | 로그인한 회원이 받으면 그 템플릿이 라이브러리에 담긴다. **처음 받을 때만** 0원 주문이 1건 생긴다. 같은 회원 + 같은 템플릿은 한 번만 담긴다. 같은 회원이 동시에 두 번 받아도 주문은 1건이고, 두 요청 모두 링크를 받는다(500이 아니다). 방문자의 받기에는 주문이 없다 | ADR-0002, ADR-0008 결정 1 |
| D-5 | 받기 응답은 라이브러리에 담겼는지를 알려 준다. 방문자에게는 "로그인하면 받은 템플릿이 라이브러리에 모입니다" 같은 안내를 띄운다. 로그인을 강요하는 창은 없다 [잠정: 문구] | ADR-0008 결정 1 |
| D-6 | 내 라이브러리는 그 회원의 주문 목록이다. 목록에 제목·썸네일·형식이 나오고, 여기서 다시 받는다 | ADR-0002, ADR-0008 |
| D-7 | 운영 계정이 템플릿을 내려도, 이미 라이브러리에 담긴 템플릿은 그 회원이 라이브러리에서 계속 보고 받는다. 상세 주소는 열리지 않는다(B-6). 권리 문제로 라이브러리에서도 막아야 하면 런북으로 파일·링크를 지우고 내린다 | 정현 11/12 |
| D-8 | 라이브러리에서 빼기는 v1에 없다 | 정현 11/12 |
| D-9 | 받을 것(파일·링크)이 아직 없거나 런북으로 지운 템플릿의 받기는 "받을 수 없음" 코드로 답한다 [잠정: 11/14, 코드 이름] | 정현 11/12 |
 
### 2-3 드롭 (R)
 
| ID | 요구사항 | 근거 |
| --- | --- | --- |
| R-1 | 모든 드롭은 여는 시각이 있다. 수량 한정이면 수량, 기간 한정이면 끝 시각이 더해지고, 둘 다면 먼저 닿는 쪽에서 끝난다. 템플릿 하나에 드롭은 하나다 | 용어 사전 "드롭", 정현 11/12 |
| R-2 | 드롭은 로그인한 회원만 받는다. 계정당 1개다 | ADR-0007 4-5, ADR-0008 결정 2 |
| R-3 | 드롭 전용 템플릿은 [라이브러리에 추가]가 선착순이다. 담으면 0원 주문이 1건 생긴다(D-4와 같은 주문). 다운로드는 그 뒤 라이브러리에서 한다. 일반 받기(D-1)로는 받을 수 없다 | ADR-0008 결정 2 |
| R-4 | 드롭 템플릿도 공개되면 목록·상세에 "드롭" 표시와 함께 나온다. 상세에는 받기 버튼 대신 여는 시각(항상), 남은 수량(수량 한정일 때), 끝 시각(기간 한정일 때)과 [라이브러리에 추가]가 있다 | |
| R-5 | 다음 넷이면 담지 않고 이유를 알려 준다: 로그인하지 않음(401), 열리기 전, 끝남(기간이 지남 또는 수량 소진), 이미 담음 [잠정: 6주 차, 코드 이름] | ADR-0008 결정 1 |
| R-6 | 동시에 몰려도 정한 수량보다 많이 담기지 않는다. 같은 계정이 동시에 여러 번 눌러도 1개만 담기고 수량도 1만 준다. 수요가 수량보다 많으면 정확히 수량만큼 담긴다(넘쳐도, 모자라도 틀린 것이다) | ADR-0001, 기획: 줄이지 않는 것 |
| R-7 | 드롭이 끝난 템플릿을 어떻게 할지(드롭 전용 유지 / 일반으로 풀기) [잠정: 6주 차] | ADR-0008 결정 2 |
| R-8 | 열렸는지·끝났는지는 서버 시각으로 판정한다. 화면의 카운트다운은 표시일 뿐이다 | 기획: 제품 규칙 |
 
### 2-4 계정 (A)
 
| ID | 요구사항 | 근거 |
| --- | --- | --- |
| A-1 | **가입(코드 먼저)**: 이메일 입력 → 메일로 6자리 코드 → 코드 입력 → 비밀번호·닉네임 입력, 이용약관 동의(필수), 만 14세 이상 확인 → 가입. 처리방침은 링크로 안내한다(동의를 받는 대상이 아니다) [확인 필요: 5주 차 처리방침과 함께]. 코드를 맞힌 뒤에만 계정이 생긴다. 코드에는 만료와 시도 횟수 제한이 있고, 다시 보내면 옛 코드는 무효가 된다. 가입 중에도 세션을 만들지 않는다 [잠정: 4주 차, 만료·횟수] | ADR-0008 결정 4 |
| A-2 | 가입 코드 보내기는 어떤 이메일을 넣어도 같은 응답("코드를 보냈습니다")이다. 이미 가입된 주소에는 코드 대신 "이미 가입되어 있습니다(로그인·비밀번호 재설정 안내)" 메일을 보낸다 | ADR-0007 3-3, ADR-0008 |
| A-3 | 로그인·로그아웃. 실패 응답은 이유(없는 계정, 틀린 비밀번호, 정지)와 관계없이 하나다. "로그인 상태 유지"를 고르면 2주 유지한다 [잠정: 4주 차, 세션 숫자] | ADR-0007 결정 2, 3-3 |
| A-4 | 비밀번호 재설정은 메일로 한다. 요청 응답은 주소와 관계없이 같다. 재설정이 끝나면 그 회원의 세션을 모두 끊고 변경 알림 메일을 보낸다. 그 뒤에는 새 비밀번호로 다시 로그인한다 [잠정: 4주 차, 링크 vs 코드] | ADR-0007 결정 2, 3-3 |
| A-5 | 내 정보에서 닉네임을 본다. "비밀번호 바꾸기"는 재설정 메일을 보낸다. 닉네임 바꾸기는 v1에 없다 | 기획: v1 범위, 정현 11/12 |
| A-6 | 비밀번호 규칙과 저장 방식은 ADR-0009를 따른다(8~20자, ASCII 영문·숫자·특수문자를 각각 하나 이상, BCrypt) | ADR-0009 |
| A-7 | 만 14세 이상만 가입한다. 가입 화면에 확인 칸을 두고, 확인 값이 없는 가입 요청은 서버가 거절한다. 만 14세 미만임을 알게 되면 A-9처럼 지운다(런북). 만 14세 미만도 로그인 없는 둘러보기·받기는 쓸 수 있다 | 정현 11/12 |
| A-8 | **탈퇴**: 내 정보에서 지금 비밀번호를 다시 넣고 탈퇴한다. 탈퇴 방법은 가입보다 어렵지 않다. 탈퇴하면 그 회원의 세션을 모두 끊는다. 비밀번호 확인은 레이트 리밋 대상이다(N-4) | 기획: v1 범위, 정현 11/12 |
| A-9 | 탈퇴하면 회원을 알아볼 수 있는 정보를 운영 DB에서 **바로** 지운다(복구 유예 없음): 회원 행, 이메일, 비밀번호 해시, 인증 시각, 닉네임, 약관 버전, Redis의 세션·가입 코드·재설정 토큰. 주문은 회원 칸을 비워 **익명으로 남긴다**. 받은 수는 바뀌지 않는다. 서버 밖 백업에는 백업 보관 기간 동안 남으며, 백업에서 복구하면 그 사이 탈퇴한 회원을 다시 지운다(복구 런북). 탈퇴한 뒤 같은 이메일로 다시 가입할 수 있고, 드롭도 다시 받을 수 있다 [잠정: 5주 차, 처리방침 문구] | 정현 11/12 |
| A-10 | 공식 제작자·운영 계정은 탈퇴하지 않는다. 역할이 있는 회원의 탈퇴 요청은 서버가 거절한다(정리는 런북) | ADR-0007 4-2·4-3 |
| A-11 | 정지된 회원은 로그인할 수 없고, 정지하면 그 회원의 세션을 모두 끊는다. 로그인 실패 응답은 다른 실패와 같다. v1의 정지는 런북 절차다 [잠정: 4주 차, 정지 안내] | ADR-0007 결정 2, 기획: v1 범위 |
| A-12 | 이메일은 앞뒤 공백을 빼고 소문자로 바꿔 저장·비교한다(가입, 로그인, 재설정, 가입 코드, 레이트 리밋이 모두 같은 규칙). 구글 메일의 점·+는 정리하지 않는다. 닉네임은 2~20자의 한글·영문·숫자이고, 공개되지 않으므로 겹쳐도 된다. 가입할 때 동의한 이용약관의 버전을 남긴다 | ADR-0007 4-3·4-5, 정현 11/12 |

### 2-6 운영 화면 (O, 운영 계정)

## 6. 정현의 판단 (대화에서 옮김)
 
> 정현의 말을 대화에서 옮겼다. 읽기 쉽게 조금 다듬었지만 뜻은 바꾸지 않았다.
 
- 비밀번호 규칙·저장 (11/12): 원문은 ADR-0009의 "정현의 판단"에 있다. 결론은 가-1과 BCrypt.
- 만 14세 미만 (11/12): "이건 가로 가죠"
- 탈퇴 (11/12): "좋습니다. 그리고 계정을 탈퇴하더라도 다운로드 수도 변동 없게 하고, 주문과 라이브러리 행도 익명으로 바꿔서 우리의 활용 가능한 데이터로 남기면 좋을 것 같아요."
- 닉네임 바꾸기 v2, 내린 템플릿의 라이브러리 유지, 라이브러리에서 빼기 v2 (11/12): "이건 셋 다 좋아요."
- 최대 노력 검토의 질문 열 개 (11/12): 열 개 모두 멘토 추천대로 정했다(탈퇴 뒤 회원 행, 드롭의 모양, 템플릿 상태, 공개 중 수정, 노션 공식, 가입 입력값, 카테고리, 받은 수, 특수문자 목록, 출시 전 잠금). 정현이 물은 것: "주문 = 라이브러리라고 생각하면 되나요?" → v1에서는 그렇다(라이브러리는 그 회원의 주문 목록). "지금 구조가 나중에 카테고리가 추가되도 유연하게 반응할 수 있는 구조인가요?" → 하나 더하는 것은 코드 값 추가와 배포 한 번이고 표는 그대로다. 출시 전 잠금은 "사이트는 실제로 존재하고 저는 들어갈 수 있다는거죠?"를 확인한 뒤 정했다(주소를 알면 누구나 화면에는 들어오지만 가입·받기는 끝낼 수 없다)
- 승인 (11/12): 검토를 반영한 뒤 바뀐 곳 일곱 군데를 읽고 "오케이 승인하고요"
